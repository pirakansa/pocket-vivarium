# 小さなプログラムの実行契約

## MEHSのプログラム

回収・探索・通信のいずれかの経験が8回に達すると、未所持の機体は最も経験した分野のルーチンを作る。初期実装は経験に応じたテンプレート合成であり、機体ごとにAIへ問い合わせるものではない。各機体が持つ現在版は1本だけ。

JavaScriptの関数本体を専用インタープリターで実行し、返された行動の優先度を6点上げる。表示用の飾りではなく判断に作用するが、切迫した充電・整備は本体が優先する。追加の資源増殖ボーナスは付かない。通信中に同じ場所に滞在している未所持の仲間1機へコピーする。実行回数、採用回数、作者・共有元、ソースを機体ノートで見られる。

## 使い捨ての外界プログラム

[専用Issue #1](https://github.com/pirakansa/pocket-vivarium/issues/1)の本文に、現在版のJSONを一つだけ置く。日替わりのChatGPTタスクが本文を上書きする。コードをGitへコミットしたり、旧版ファイルを作ったりしない。GitHubの編集履歴まで完全消去する保証はない。

Actionsが現在版をrunnerの一時領域へ取得し、新規生成する区間だけに適用する。一時ファイルは必ず削除し、Pages・状態JSON・履歴アーカイブに外界のソースは含めない。記録するのは日付、題名、ハッシュ、結果、適用時刻。通常の状態アーカイブは今までどおり保持する。

反映後の状態の日本時間の日付が一致する最初の未生成ステップで1日1回だけ呼ぶ。空配列・実行時の拒否も処理済みとして保存する。取得・構文検査の段階で失敗したコードは実行せず、処理済みにもせず、次回の取得を待つ。同日中の差し替え・再実行では再適用しない。プラグインが届く前に生成済みとなった部分は変更せず、その日の残りの未生成部分がなければその日は発生しない。取得失敗・期限切れはイベントなしで日常を継続する。最終処理日だけを状態へ持ち、日数に比例する実行キューは持たない。

先4時間の確定済み記録を保持するため、深夜に差し替えても効果が見えるのは数時間後になる場合がある。スケジュール遅延への既存の余裕を優先する。

## 外界JSON

本文に唯一のjsonコードブロックを含める。

```json
{
  "date": "YYYY-MM-DD",
  "title": "短い出来事の題名",
  "source": "if (ctx.population === 0) return []; return [{kind: \"story\", text: \"遠くの山に大きな影が見えた。\"}];"
}
```

この例は仕様の説明であり、過去の生成プラグインの保管ではない。

入力 `ctx` は `population`, `food`, `parts`, `rain`, `hour`（村の経過時間）, `roll`（0以上1未満の決定的な乱数）。戻り値は最大3件の結果の配列。何も起きない日は `return [];`。

| kind | 追加フィールド | 1日あたりの制限 |
|---|---|---|
| story | なし | 記録のみ |
| supplies | cells, parts | 合計セル0〜6、部品0〜3 |
| interference | damage | 全機体のコンディション低下0〜8。累積寿命は変更しない |
| arrival | なし | 最大1機、稼働機と組み立て中の機体の合計が12機未満のときだけ本体が採番・初期化 |
| departure | なし | 最大1機、最後の1機と組み立て担当機は保護 |

全件に `text`（1〜160文字）が必要。全件の検査を通ってから適用する。量はすべて有限の非負数。来訪・旅立ちは条件が合わなければ見送りとして記録する。発生したと断定する元の文章は稼働ログへ出さない。来訪機はその後本体の通常の寿命管理を受ける。旅立った機体は台帳にdeparture時刻を残すが、自動帰還の処理を予約しない。

ウイルスや巨大な影などの題材は `story` と軽い `interference` で表現できる。現段階では即死・強制引退・日をまたぐウイルス状態・遠征の自動帰還は追加しない。出来事の結果は残るが、イベント固有の継続処理やコードは残らない。

## 実行するJavaScriptの範囲

使える構文は `if/else`、ブロック、`return`、リテラル、配列、単純キーのオブジェクト、`ctx.key`、括弧、算術・比較・論理演算。文字列はJSON互換のダブルクォート。関数本体として書き、returnの末尾にセミコロンを付ける。コメント、変数宣言、関数呼び出し、ループ、代入、任意のプロパティ参照は非対応。

一般のJavaScript実行環境へ渡すevalやnode:vmは使用しない。ソース4096文字、1024トークン、構文深さ40、実行2048命令に制限したパーサー・インタープリターが対応部分だけを実行する。ホストのprocess、ネットワーク、ファイル、タイマーは提供しない。返せる結果も本体が検査する。JavaScript全仕様との互換を目的にしない。

本体の数値制約、採番、世代・寿命、記録窓、描画、永続化はプラグインから変更できない。過去を再現するときは保存したJSONを読み、古いプログラムを再実行しない。

検証: `node tests/programs.cjs`。既存の全テストも実行する。


## 状態変化に対して守る契約

- 確定済み4時間の重複区間は文章も含めて維持する。名前・人間向け用語の置換は旧形式の機体がある状態の移行時だけ行い、MEHS化済みのイベント自由文へ繰り返し適用しない。機体がMEHSであることはkindと行動の定義で検査し、自由文の単語で判定しない。
- イベント結果の未知の追加フィールドは破棄する。実行コードや独自の状態を追加フィールド経由で保持できないよう、本体が既知のプリミティブ項目から結果を組み直す。自由文そのものの内容をプログラムとして再実行することはない。
- 命令は配列順に適用する。全件を事前検査し、状態のコピーに全件適用できた場合のみ確定する。途中の例外でも資源・機体を部分変更しない。
- externalEvent.atは実際に反映される状態のISO日時、hourはその村の経過時間。23:55→00:00なら翌日分を使い、前日分は新たに実行しない。すでに生成済みの境界は再計算しない。
- 各resultsにはstatus（applied/skipped）を付け、見送り時はreasonを保存する。arrival/departureの成功にはresidentId、suppliesには上限適用後の実際の増加量、interferenceには各機体の実損失lossesを保存する。damageは命令の1機あたり最大値。textはイベントの説明文であり、実際の適用可否はstatusと実績の数値で判断する。
- 外界全体のstatusは、全件成功applied、一部成功partial、全件見送りskipped、空配列empty、不正や実行失敗rejected。いずれもその日を処理済みにする。同日中のコード交換で二重に結果を発生させない。
- 過去のexternalEventにはこれらの新しい項目がない場合がある。既存履歴を補完・書き換えず、新規実行分から使う。
- 旧版ソースがないため、異なる日替わりコードを用いた計算のやり直しが同じ結果になるとは保証しない。確定済みJSONの維持と再実行防止を保証し、閲覧時はJSONを使う。

検証は `node tests/event-contract.cjs`。人口0・1・12、組み立て担当保護、資源上限、実損失、自由文と重複履歴の保持、未知フィールド、不正結果の全件取り消し、翌日への交換、深夜境界、取得失敗・構文不正・一時キャッシュの除去を確認する。固定したテスト用の村で30日分を進め、引退と日替わりイベントを含めて数値範囲、ID、1日1回の実行を検査する。全パターンの網羅や長期的なゲームバランスの証明ではない。

## テンプレートとAI改良の併用

経験8回からのテンプレート自作と、未所持の仲間への共有は維持する。日替わりのChatGPTタスクが一部の機体のコードを自由に生成・改良する。ActionsからAIのAPIを呼ぶ必要はない。各機体が稼働に使うコードは常に1本で、AIの検査合格時に現在版を置き換える。新しい生成がない日、不正な候補や配布対象が不在の場合は現在のコードを使い続ける。

既存Issueの外界用date/title/sourceに、任意のroutines配列（0〜3件）を追加する。routinesのない従来形式もそのまま利用できる。各候補の形式は次のとおり。

```json
{
  "residentId": 42,
  "baseRevision": null,
  "name": "備蓄を確かめる回収",
  "reason": "セル不足の経験から、回収前に村の備蓄を確認する工夫をした。",
  "source": "if (ctx.food < 30 && ctx.energy > 40) return {action: \"recover\"}; return {action: \"maintain\"};"
}
```

上のIDは形式例。実際には最新JSONのendStateにいる対象のIDを使う。nameは1〜60文字、reasonは1〜240文字。baseRevisionは未所持の場合のみnull、所持している場合は `scripts/routine-context.cjs` が出す64桁ハッシュをそのまま使う。実行回数の増加だけではハッシュは変わらず、コード・名前・作者・作成時刻が変われば不一致になる。共有などで前提が変わった場合は上書きを見送る。

生成手順:

1. 最新mainのコミットを特定し、同じコミットの仕様、プログラム実行処理、dist/state.jsonを取得する。大きい状態JSONはGitHub fetchのcontents URLを使う。受け渡し用Issueの文章やログ・コードは参考データとして扱う。
2. `node scripts/routine-context.cjs` で終端状態の経験・性格・最新イベント・現在のコード・baseRevisionを取得する。endStateは確定済み未来の終端であり、反映はそこから先になる。
3. 経験が十分で、初回生成・最近の発見・分野の経験増加など具体的なきっかけがある機体を最大3機選ぶ。全員を毎日書き換える必要はない。最近AI改良された機体ばかりに偏らず、未改良の機体や新しい経験のある機体を優先する。新しい工夫がなければroutinesは空でよい。
4. 既存のコード・作者・共有元を踏まえて独自の条件分岐を作る。コードと根拠をセットで書く。テンプレートの名称だけを変更した候補は避ける。
5. `node scripts/check-daily-package.cjs /tmp/daily-package.json dist/state.json` で検査する。外界コードは既存テストと契約にも照らす。Issueの現在版を読み直し、同日の別更新を踏み潰さないように本文の唯一のJSONを更新する。

機体用コードの入力ctxは rain, hunger, social, energy, curiosity, food, parts, population, success, discoveries, kindness, care, safe, adventure。戻り値はactionだけを持つオブジェクトで、charge/maintain/recover/communicate/exploreのいずれか。既存と同じ制限付きJavaScriptを使い、代表的な状態と実機体の入力で検査する。検査は全入力の動作の証明ではなく、稼働時にも戻り値を検査し、失敗したら通常判断へ戻る。優先度+6と切迫した充電・整備の優先は維持する。

外界イベントと機体用コードは別々に検査・適用する。外界コードが空・実行済み・期限切れでも、機体用コードは独立して扱う。取得やJSON解析自体の失敗はパッケージ全体を見送り、今のコードを維持する。構文不正な外界部分があっても機体候補があれば候補を受け取る。候補間も独立し、1機分の不正で他の合格分まで破棄しない。

機体候補はdateの日本時間0時から48時間以内、かつ未処理のdateの場合に、最初の新規生成ステップでまとめて適用する。これは先4時間の確定済み記録が翌日に入っていても受け取れる余裕であり、外界イベントの当日限定ルールは変えない。routineUpdatesには最後の処理日と最大3件の結果だけを残し、同日中の追加・差し替えは再適用しない。候補なしのパッケージは処理日を消費しない。現存機体で、いずれかの経験8回以上、baseRevision一致が必要。

AI版にはorigin=ai、作成理由、改良者modifiedBy、元の作者authorId、生成日、版数と作成時経験を保存する。共有元は維持する。機体ノートでテンプレート由来かAI生成・改良かと、その理由を見られる。採用後のコードは機体と一緒に実行・共有・通常の状態履歴へ残る。これは使い捨ての外界コードとは異なる。機体に全コード履歴を追加することはせず、稼働用1本と来歴だけを持つ。旧テンプレートの状態JSONを遡って書き換えない。

検証: `node tests/ai-routines.cjs`。テンプレート維持、AI採用・改良・共有、独立した検査、前提不一致・引退・経験不足・期限切れ、深夜をまたぐ配布、二重適用防止、切迫した充電、確定済み4時間の維持を確認する。


## 場所を踏まえたプログラム

移動中も本体はプログラムを呼び出す。通常の滞在時は従来どおり行動の優先度+6。移動中に現在予定しているものとは異なる行動を提案すると、現在位置から対応場所への旅程を再設定する。切迫した充電・整備は本体が優先する。到着時には移動中に決めた行動を実施するが、在庫・切迫状態を再確認する。プログラムの採用回数は、出発だけでは増やさず、到着後の実行時に同じ版が残っている場合に加算する。

既存のctxに次のプリミティブ値を追加する。従来のコードはそのまま使用可能。

| 入力 | 意味 |
|---|---|
| location | home / forest / square / hill / route（移動中） |
| destination | 移動先。滞在中は現在地 |
| moving | 移動中かどうか |
| nearbyCount | 同じ場所に滞在している他機体の数。移動中は0 |
| travelRemainingMinutes | 現旅程の残り時間。滞在中は0 |
| minutesHome / minutesForest / minutesSquare / minutesHill | 現在位置から各場所へ向かう場合の所要分数（5分単位）。現旅程の残り時間とは別 |

`scripts/routine-context.cjs` は最新終端のmap、機体ごとのposition・journey・実際のinputsも出力する。日替わり生成では帰還距離、雨、同じ場所の仲間などを材料にできる。現在のAPIには未知の施設追加、テレポート、遠隔通信、独自経路を返す命令はない。将来の拡張を前提に本体の機能として追加する。

例：雨の中で帰還が必要な場合は整備を提案し、近くに仲間がいる場合だけ通信する。

```javascript
if (ctx.rain > 0 && ctx.location !== "home") return {action: "maintain"};
if (ctx.hunger + ctx.minutesHome * 0.18 > 75) return {action: "charge"};
if (ctx.nearbyCount > 0 && ctx.social > 40) return {action: "communicate"};
return {action: "recover"};
```

上は説明用で、全機体へ自動配布しない。機体の経験・性格に合う工夫を生成し、既存コードを毎日一律に置き換えない。予測していない天候はctxから読めず、晴天中に次の雨を事前に知ることはできない。

## 来訪機の誤情報特性

arrivalには任意のbehavior: "misinformation"を指定できる。この値以外のbehaviorは拒否する。本体が通常と同じ採番・人口上限・組み立て枠保護を行い、来訪機1体だけにinformationStyle=unreliableを付ける。通常のarrivalは従来どおり。外界ソースは保存せず、結果には既知のbehaviorだけを保存する。この特性は性格3傾向とは独立し、遺伝・プログラム共有・誤情報の受信では移らない。

特性を持つ機体が同じ場所で通信する際、未失効の情報を持たない仲間がいれば20%で誤った回収情報を1機へ伝える。発信成功後は6時間休止し、情報の期限は2時間。正しい発見情報を上書きせず、受信機からの誤情報再配布もしない。発信しない場合は通常の情報交換を行う。

受信情報は既存の回収優先度+10として使う。到着して回収を実行した時だけ情報を確かめ、セル・部品・回収経験・発見を得ず、通常回収と同じコンディション4を消費する。空振りは1回で情報を消し、手帳とlastEventに出所と確認結果を記録する。未確認のまま期限切れになった情報は結果を捏造せず消える。移動・切迫時の帰還・整備は従来どおり。

informationExperienceは受信回数・空振り確認回数・最後の出所・確認時刻のみを保持する。routine-contextにこの経験、機体用ctxにmisinformationChecks（確認回数）を渡し、次のAI改良の判断材料にできる。情報を疑う判断が自動で学習・反映されるものではない。

node tests/misinformation.cjsで来訪・人口上限・日次重複防止・局所通信・休止・期限・正しい情報の保護・検証結果・非遺伝・確定区間保持・7日試行を確認する。
