# Pocket Vivarium — こもれびの村

住人の暮らしを眺める箱庭。GitHub Actionsで2時間分の状態を生成・記録し、GitHub Pagesで再生します。

## 起動

```sh
python3 -m http.server 8000 --directory dist
```

http://localhost:8000 を開きます。JSON取得のためHTTPサーバーが必要です。追加のパッケージインストールやビルドは不要です。生成スクリプトとテストはNode.js 22で実行します。

## 自動更新・公開

`.github/workflows/deploy-pages.yml` が以下を実行します。

| 起動方法 | 状態生成 | Pages公開 |
|---|---|---|
| 2時間ごとのschedule | 未生成の時間帯を計算・記録 | 実行 |
| mainへのpush | 実行しない | 実行 |
| 手動実行 | `update_state` を選択した場合のみ | 実行 |

スケジュールは `17 */2 * * *`（UTC）。日本時間では毎日 **01:17、03:17、…、23:17** の12回です。混雑しやすい毎時00分を避けています。実行時刻は保証されず、遅延や実行漏れがあり得ます。

1. 最新mainを取得し、生成処理のテストを実行。
2. 前回の `endState` から5分刻みの24時点と120分後の終了状態を生成。
3. 生成後の再生テストが成功した場合だけJSON・履歴をコミット。
4. 同じワークフロー内で `dist/` をPagesへ公開。

自動コミットは `github-actions[bot]` のnoreply名義です。`GITHUB_TOKEN` によるpushは別のpushワークフローを起動しないため、その実行内で公開まで完了します。別トークンやAI APIは不要です。

初回は **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。Actionsの書き込みやmainへの直接pushを禁止している場合は、生成記録の保存が許可されるようリポジトリ側の設定を調整してください。push失敗時には公開も停止し、force pushは行いません。

手動では **Actions → Update village and deploy Pages → Run workflow** で `update_state` を選択します。同じ2時間の実行枠を再実行しても村は追加で進みません。テスト用に何度でも進めたい場合は別の作業コピーで次のローカルコマンドを使用し、必要に応じて `update(root, date)` に別時刻を渡してください。

```sh
node scripts/update-state.cjs
```

## 時間と継続性

- JSONの時刻は村の中の相対時間です。現実の時刻に合わせて再生する機能はまだありません。
- スケジュールの現実時間は `generatedSlot` で識別し、二重更新を避けます。`generatedAt` は実際の完了日時ではなく、その実行枠の開始日時です。
- 初回は現在のサンプルの終了状態から次の2時間を生成します。過去の現実時間へはさかのぼりません。
- 以降、未実行の2時間枠があれば順番に計算して追いつきます。1回の実行では最大84枠（7日相当）を処理し、残りは後続実行へ引き継ぎます。
- これは事前生成した2時間分の記録を見る方式です。端末上でシミュレーションを実行しません。

## シミュレーション

空腹・体力・交流欲求・好奇心、性格の重み、採集経験、食料、天候、村の時刻から行動の優先度を計算します。食事・休息・採集・交流・探検があり、夜は休息を優先します。睡眠専用の状態は未実装です。

欲求は5分ずつ変化し、行動を短時間継続した後で次の選択を行います。状態は前の結果を引き継ぎます。生成AIや外部サービスの呼び出しはありません。現在は簡易なルールベースで、天候の自動変化・人間関係・生死などは未実装です。

## 状態と履歴

- `dist/state.json`：最新の2時間分。`schemaVersion: 2`、`mode: "relative"`。
- `frames`：`minute` が0, 5, …, 115の24時点。
- `endState`：120分後の終了状態。次回生成へ引き継ぎ。
- `data/history/`：過去の2時間分を直近168本まで保持（通常更新14日相当）。初回は従来のサンプルも保存します。
- 履歴のファイル名は村の開始時点の通算分数。Gitの履歴は別途残ります。履歴ファイルはPages公開対象外ですが、公開リポジトリ上では読めます。
- 村の手帳は各状態内で直近35件を保持。過去バッチを画面で選ぶ機能はまだありません。

## フロントエンド

- 初期速度は×30（2時間を4分で）。×1・×30・×120、一時停止、±5分、最初から、スライダーに対応。
- 起動時にJSONを読み込み、0分から再生。localStorageや現実日時との連動はありません。
- 開きっぱなしの画面は新しいJSONを自動取得しません。更新後の記録を見るにはページを再読み込みしてください。
- タブ非表示中は再生時間を進めません。120分で記録の再生を終了し、見た目の動きは続きます。
- 記録の間も住人は活動場所の周りを動きます。表示用の座標と読み込んだ状態は別管理です。
- 巻き戻すと数値・行動・手帳をその時点へ戻します。

## 検証

```sh
node tests/player.cjs
node tests/update-state.cjs
```

再生・巻き戻し・非表示時の停止、生成の連続性・二重更新防止・実行漏れ補完・履歴保持を確認します。

## 管理・公開先

ソースと記録はGitHub、画面の公開はGitHub Pagesへ統一しています。Sitesは廃止済みです。公開URLは成功したActionsの `github-pages` Environmentから確認できます。

公式手順: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
